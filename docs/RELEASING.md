# PureWall Release Guide

This guide is for maintainers preparing a Windows release. It describes the repository's release automation and verification boundaries; it does not mean that a release, signature, or installer smoke has already run.

## Release contract

- Use a strict `v<major>.<minor>.<patch>` tag, such as `v0.1.0`.
- The tag must match the versions in `package.json`, `src-tauri/Cargo.toml`, and `src-tauri/tauri.conf.json`.
- Tag pushes run `.github/workflows/release.yml` on `windows-latest`.
- The workflow creates **only a draft** GitHub Release. Publishing is a deliberate maintainer action.
- `workflow_dispatch` is a dry-run unless `publishDraft` is explicitly enabled with an existing tag.
- No unrun workflow counts as evidence. Record evidence from the matching draft or published release.

Before a first release, obtain the first green run of `.github/workflows/ci.yml`, confirm GitHub Private Vulnerability Reporting is available, and complete the review gate in [SECURITY.md](../SECURITY.md).

## Required GitHub Actions configuration

Provision these **secrets**. Store values only in GitHub Actions; never commit them or print them in logs:

```text
WINDOWS_CERTIFICATE                 base64-encoded Authenticode PFX
WINDOWS_CERTIFICATE_PASSWORD        password for the PFX
WINDOWS_CERTIFICATE_TIMESTAMP_URL   HTTPS RFC 3161 timestamp server
TAURI_SIGNING_PRIVATE_KEY           Tauri updater signing private key (base64)
TAURI_SIGNING_PRIVATE_KEY_PASSWORD  optional updater-key password
```

Provision this repository **variable**:

```text
TAURI_SIGNING_PUBLIC_KEY             Tauri updater signing public key
```

Keep the public key and certificate recoverable in protected storage. Losing the updater private key or allowing the code-signing certificate to expire blocks future signed releases. Use an HTTPS timestamp service so valid Authenticode signatures remain verifiable after certificate expiry.

## Tag and draft flow

1. Confirm the working tree, changelog, version declarations, and release notes are ready.
2. Run the local, secret-free contract checks:

   ```powershell
   npm ci
   npm run test:release-contract
   npm run verify:release
   ```

3. Provision or verify the GitHub secrets and public-key variable.
4. Push the authorized tag, for example `git push origin v0.1.0`.
5. Confirm the workflow checked out that exact tag, passed its Windows build/test gates, and created a **draft** release.
6. Review the draft artifacts using the checklist below. Do not publish yet.

The workflow's signing configuration is generated by `scripts/prepare-release-config.ps1`; it is ignored and must not be committed. Artifact collection and `SHA256SUMS.txt` generation use `scripts/collect-release-artifacts.ps1`.

## Draft review checklist

For every MSI and EXE in the draft:

1. Verify Authenticode status is `Valid` and the signer is the expected release identity.
2. Verify every artifact against the matching `SHA256SUMS.txt` line.
3. Verify the updater `latest.json` and `.sig` files correspond to the release artifacts and public key.
4. Verify GitHub artifact provenance with `gh attestation verify`.
5. Run the disposable Windows installer smoke workflow for clean install, optional upgrade, and uninstall.
6. Record the exact release tag, workflow run, artifact names, hashes, signatures, attestation result, and smoke result.
7. Publish only after the evidence is complete and the maintainer approves the draft.

### Checksum verification

Run in PowerShell from the directory containing the downloaded artifact and checksum file:

```powershell
Get-FileHash .\PureWall_0.1.0_x64-setup.exe -Algorithm SHA256
Get-Content .\SHA256SUMS.txt
```

The hash must exactly match the corresponding filename in `SHA256SUMS.txt`.

### Authenticode verification

```powershell
Get-AuthenticodeSignature .\PureWall_0.1.0_x64-setup.exe |
  Format-List Status,StatusMessage,SignerCertificate
```

The expected status is `Valid`, with the signer described by the release notes. Do not bypass an unexpected SmartScreen or signature warning.

### GitHub attestation verification

```powershell
gh attestation verify .\PureWall_0.1.0_x64-setup.exe --repo WiseZenn/PureWall
```

Checksums, Authenticode, Tauri updater signatures, and GitHub provenance are separate controls. A passing one does not replace the others.

## Installer lifecycle smoke

`.github/workflows/installer-smoke.yml` runs only on a disposable `windows-latest` runner through `workflow_dispatch`. It downloads the matching release artifacts, verifies checksum and provenance, then invokes `scripts/verify-install-lifecycle.ps1 -DisposableRunner` for clean install, optional upgrade, and uninstall.

The smoke workflow does not publish, edit, or delete a release. It remains **NOT RUN** until a signed draft or published release exists. A local script self-test is useful contract coverage, but it is not disposable-runner evidence.

## Local dry-run helpers

These commands do not require signing secrets and must not be presented as a signed-release result:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/prepare-release-config.ps1 `
  -ConfigOnly -UpdaterPublicKey 'LOCAL_TEST_PUBLIC_KEY' `
  -CertificateThumbprint '0000000000000000000000000000000000000000' `
  -TimestampUrl 'https://timestamp.test.invalid'
powershell -ExecutionPolicy Bypass -File scripts/collect-release-artifacts.ps1 -SelfTest
powershell -ExecutionPolicy Bypass -File scripts/verify-install-lifecycle.ps1 -SelfTest
```

See [ROADMAP.md](../ROADMAP.md) for the current evidence status. Until an authorized tag produces a reviewed matching release, signing, updater delivery, provenance, installer smoke, and publication remain pending.
